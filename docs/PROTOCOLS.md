# Добавление протокола

Описание протокола — JSON, который можно создать в приложении. Конструктор и вкладка JSON редактируют один документ. Ключей в нём нет: они привязываются к паре `protocol id + serial` отдельно в карточке прибора.

## Минимальный рабочий пример

Этот формат учебный, открытый. Сохраните JSON в файл, импортируйте через «Протоколы», проверьте пакет ниже и нажмите «Сохранить».

```json
{
  "version": 1,
  "id": "sample-water",
  "name": "Учебный открытый счётчик",
  "kind": "water",
  "source": "manufacturer",
  "companyId": 123,
  "prefix": "B1",
  "identity": { "offset": 1, "length": 2 },
  "encryption": { "mode": "none", "offset": 3, "length": 7 },
  "fields": [
    { "id": "total", "label": "Объём", "type": "u32", "offset": 0, "endian": "little", "scale": 0.001, "unit": "м³", "role": "reading" },
    { "id": "battery", "label": "Батарея", "type": "u8", "offset": 4, "endian": "little", "scale": 1, "unit": "%", "role": "battery" },
    { "id": "temperature", "label": "Температура", "type": "i16", "offset": 5, "endian": "little", "scale": 0.01, "unit": "°C", "role": "temperature" }
  ]
}
```

Пакет для вкладки проверки: `B1 03 E9 40 E2 01 00 5E FB FF`. Ключ оставьте пустым. Результат: ID `03E9`, объём `123.456 м³`, батарея `94%`, температура `−0.05 °C`.

## Сопоставление advertising

| Параметр | Значение |
| --- | --- |
| `version` | Сейчас только `1` |
| `id` | Уникальное имя: 1–64 символа `a-z0-9._-`, первый — буква/цифра; `demo-` зарезервировано |
| `name` | Отображаемое имя до 100 символов |
| `kind` | `water`, `electricity`, `gas`, `heat`, `other` |
| `source` | `manufacturer` или `service` |
| `companyId` | Для manufacturer: целое десятичное 0–65535 |
| `serviceUuid` | Для service: полный UUID, например `0000181a-0000-1000-8000-00805f9b34fb` |
| `prefix` | Непустой HEX-префикс payload; пробелы допустимы |
| `identity.offset/length` | Срез открытой части payload для серийного номера: длина 1–32 байта |

**Нулевой байт payload:** для Manufacturer Data — первый байт после Bluetooth Company ID, для Service Data — первый байт после Service UUID. Сырые пакеты из внешнего сниффера могут включать дополнительные AD length/type/UUID/company поля. Уберите их перед использованием в тестере. Отрицательные/дробные смещения запрещены.

Сначала выбирается источник и Company ID / UUID, затем проверяется prefix. Пересекающиеся префиксы пользовательских протоколов для одного источника запрещены; при неоднозначном сопоставлении пакет не декодируется. Учебные протоколы `demo-*` не распознаются в реальном приёме.

Идентификатор прибора считывается **до расшифровки**. Укажите стабильный серийный номер, а не случайный Bluetooth-адрес. Если идентификатор находится внутри шифротекста, потребуется расширение C++ пути выбора ключа.

## Расшифровка

Все позиции относятся к исходному payload; `fields[].offset` относится уже к выделенным/расшифрованным данным.

| Параметр | Значение |
| --- | --- |
| `mode` | `none`, `aes-128-ctr`, `aes-128-cbc`, `aes-128-ccm` |
| `offset` | Начало открытых данных или шифротекста |
| `length` | Число байтов данных; `-1` — остаток пакета без CCM тега |
| `nonceOffset` | Начало nonce / IV в исходном payload |
| `nonceLength` | CTR и CBC — 16, CCM — 7–13 |
| `tagLength` | Для CCM: 4, 6, 8, 10, 12, 14 или 16 |
| `aadLength` | Для CCM: число AAD-байтов с начала исходного payload |

- Ключ для всех AES-режимов: 16 байт / 32 HEX-символа.
- В CCM тег расположен непосредственно после шифротекста; AAD, nonce и tag участвуют в проверке. Ошибка ключа, тега или аутентифицируемых данных не выдаёт показание.
- В CTR весь 16-байтовый nonce — начальный блок счётчика. Mbed TLS увеличивает его как 128-битовое число с big-endian порядком. Короткие nonce и особые способы построения counter block требуют расширения декодера.
- В CBC `nonce` означает IV; длина шифротекста должна быть кратна 16. Возвращаются сырые блоки без удаления padding. Описывайте поля полезных данных, не захватывая заполнение.
- CTR/CBC не подтверждают подлинность, правильность ключа или отсутствие модификации. Нельзя считать успешное чтение чисел проверкой ключа.

Учебный CCM-формат лежит в `protocols/demo-water.json`: prefix (1), serial (2), nonce (7), шифротекст (7), tag (4) — 21 байт. У электричества меняются prefix и масштаб. Демо не передаёт Bluetooth-пакеты в эфир: генератор подаёт их непосредственно в тот же путь обработки, который использует сканер.

## Поля

Каждое поле содержит `id`, `label`, `type`, `offset`, `endian`, `scale`, `unit`, `role`. Результат равен прочитанному числу, умноженному на `scale`.

| `type` | Формат |
| --- | --- |
| `u8` | Беззнаковый 1 байт |
| `u16`, `u32` | Беззнаковые 2/4 байта |
| `i16`, `i32` | Знаковые 2/4 байта, two's complement |
| `float32` | IEEE-754, 4 байта; NaN/Infinity отклоняются |
| `bcd` | Packed BCD, дополнительный `length` 1–6; цифры A–F отклоняются |

`endian`: `little` или `big`. В BCD little-endian меняет порядок байтов, но не тетрад внутри байта. `scale` — конечное ненулевое число; для литров в кубометры используйте `0.001`.

`role`: ровно одно `reading` для главного показания; дополнительно `battery`, `temperature`, `status`, `other`. Заряд батареи интерпретируется как 0–100%; значения вне диапазона отклоняются. Статусы показываются как числа. Битовые маски, текстовые таблицы значений и формулы пока не поддерживаются.

При сохранении изменений протокола его ранее накопленная история сбрасывается, а последний пакет декодируется заново. Так значения разных схем и масштабов не смешиваются в одном графике.

## Когда JSON недостаточно

Если прибор применяет другой шифр, производные ключи, разнесённый nonce, контрольную сумму/специальный MAC, разбиение сообщения или битовые поля:

1. Добавьте новый режим/параметр в `Protocol::parse` и `Protocol::decode` (`src/protocol.cpp`), сохраняя строгую валидацию и проверки границ.
2. Для нестандартного определения серийного номера измените `identity` и выбор ключа в `Backend::ingest`.
3. Добавьте в `tests/tst_protocol.cpp` эталонный пакет, ожидаемые поля, неверный ключ и повреждённые/усечённые варианты. Для криптографии используйте существующий поддерживаемый примитив Mbed TLS.
4. Добавьте параметр в конструктор QML и документацию. Не исполняйте код из импортируемого JSON и не записывайте ключ в описание.

## Проверка с настоящим прибором

Сравните расшифрованное значение с дисплеем прибора. Проверьте неверный ключ, низкий заряд, изменение Bluetooth-адреса, несколько приборов одинаковой модели, долгий интервал пакетов, сворачивание и повторный запуск приложения. Проверяйте, что серийный номер стабилен, а время последнего успешного показания не подменяется временем ошибки.
